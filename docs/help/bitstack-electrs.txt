bitstack electrs -- manage the onion identity publishing electrs' Electrum RPC

Usage:
  bitstack electrs
  bitstack electrs rotate [-f|--force]
  bitstack electrs set key <private_key>
  bitstack electrs logs [-f|--follow]

With no subcommand, prints this help. To print the current onion address
instead of changing it, see 'bitstack get-onion help'.

What it does:
  logs [-f|--follow]
    Prints the electrs service's docker logs. With -f/--follow, streams
    them continuously instead of printing the current buffer and exiting.

  rotate
    Discards the current onion address and lets Tor generate a brand-new
    one. Irreversible -- the old address stops resolving the moment its
    key is gone. Prompts for confirmation unless -f/--force is given.

  set key <private_key>
    Installs a specific Tor v3 onion service private key instead of
    generating one, so the resulting .onion address is one you already
    control -- e.g. restoring a previous identity, or a vanity address
    generated with a tool like mkp224o. Accepts the "ED25519-V3:<base64>"
    form (as used by Tor's ADD_ONION control command and most
    vanity-address generators) or the bare base64 of the same 64 raw
    bytes. Only the secret key is written; Tor derives the matching public
    key and .onion hostname from it itself on next start -- the same code
    path it uses to derive them for a freshly generated key, so there is
    no need to supply those separately.

  rotate and set key both stop the 'tor' service, replace the
  hidden-service key material in the 'tor-hidden-service' docker volume,
  restart the service, and wait for the (new) onion address to publish --
  caching it to .bitstack-onion, same as 'bitstack get-onion' does.
  Node data, electrs, and bitcoind are untouched throughout; only the tor
  service is bounced.

The address is stable across restarts and redeploys (the key lives in a
docker volume) -- rotate/set key change it deliberately; nothing else does.

Requires the stack to be running ('bitstack up' first). rotate and set key
also reuse the already-built local/tor image to touch the volume, so
neither needs an extra download or build.

  bitstack electrs help
  bitstack help electrs
